Challenge 11 of 15 Reversing Solved · 100 pts

BlackHat MEA 2026 · Qualifiers

upyx.

Are you familiar with python? If not, follow my friend’s advice, "don’t rename this file."

Reversing· 100 points· 4 November 2026

TL;DR

An 11.8 MB PE that is UPX over PyInstaller over 100 nested marshal layers over a Cython GUI over a custom VEH packer. The final gate is a 960-byte keyed comparison that inverts cleanly, and the last hop is a named-pipe service hidden in the UPX stub tail that <code>upx -d</code> throws away.

Solved on the day; the value was not recorded in the report.

01Recon

Sample: Challenge.exe, 11,818,598 bytes, PE32+ x86-64.

enhanced.pyd is Cython built with CYTHON_COMPRESS_STRINGS plus a hand-rolled obfuscation layer: every arithmetic operator is a module-level lambda (so the decompilation contains no raw ^ & | * + - << >> %), every string literal is XOR-obfuscated with the fixed 17-byte keystream a69cf2432ece2c576eb85e17f8cd9bb8af, and every call goes through a dispatcher that resolves globals by a ror13 name hash, making the call graph invisible statically. All 45 obfuscated constants were decoded: GUI strings, kernel32 API names, and both pipe names \\.\pipe\supyxsvc and \\.\pipe\upyxsvc. No flag material.

02The bug

The hint is the key derivation. check.pyd walks PEB -> ProcessParameters -> CommandLine (gs:0x60 → [PEB+0x20] → Length at +0x70, Buffer at +0x78, CommandLine, not ImagePathName), takes the characters after the last., keeps alphanumerics, lowercases, and FNV-1a hashes them with a non- standard basis:

Rename Challenge.exe and K changes and nothing validates, "don't rename this file." The hint is in fact sharper than that: the key is whatever follows the last. on the command line, so running the module under python.exe -u script.py makes the extension "py".

The exploitable structure is in the verifier. check.check() writes {0x11} to a handle and reads 960 bytes, then runs a per-byte comparison whose transform is a bijection in the input byte for fixed context, and whose context uses only earlier bytes. That makes the required 960 bytes unique and invertible position by position.

03Exploitation

  1. Unwrap. upx -d, carve the PyInstaller CArchive (997 TOC entries), peel main.pyc's 100 nested exec(marshal.loads(zlib.decompress(base64.b85decode(BLOB)))) layers down to import enhanced; enhanced._c605a4bf().
  2. Decrypt check.pyd. It is packed with a custom UPYX VEH packer, four encrypted regions decrypted on demand through a vectored exception handler. All four were decrypted statically.
  3. Model the verifier.

with const960 at.rdata VA 0x1800191f0 and

Every TAB[pos] is odd, so F is a bijection in x, invert it position by position.

  1. Invert. required_960.bin, md5 0858d44140df33712e1cb7fb52f0c61c, unique, and verified four independent ways: analytic inversion; Unicorn emulation of the prologue with a synthetic PEB; executing the real binary (check.check() accepts any path, so a 961-byte file substitutes for the pipe, WriteFile overwrites byte 0 with 0x11 and ReadFile returns the 960 candidate bytes); and a model-free guard-page oracle, placing the buffer against PAGE_NOACCESS makes the correct byte the one that faults, since the loop only reads buf[i+1] if buf[i] matched.
  2. The client model. The 960 bytes are 60 blocks of 16, one per typed character. Per keypress:

So the flag is exactly 60 characters, and block_n = g(t_n) where g is whatever the pipe service answers.

  1. Find the service. This is the part every static pass missed. The pipe names appear in the packed file only, upx -d discards them. In the tail of UPX1 sits an inserted native stub (~250 KB of obfuscated code, the two pipe names, a 480-byte blob at 0x5af20, then a jmp to the original entry point). Running Challenge.exe under wine + Xvfb and enumerating named pipes shows both pipes open, the service was inside the executable all along.
  2. Query it. A small mingw bridge (CreateFileA/WriteFile/ReadFile/CloseHandle) turns the pipe into a scriptable oracle. It confirms 0x00 → seed, and that 0x01 + t is a pure function of t (identical replies on repeat). recover_flag.py then needs at most 60 x 65 = 3900 queries: for each position, try each on-screen character and keep the one whose 16-byte reply matches required_960.bin[16n:16n+16].

04Dead ends

  • EXTKEY is a hash, not a length. An earlier pass read the third argument of FUN_18000e99e as the length of the extension (3). It is EBX, the FNV-1a hash of the lowercased extension. This changed the required buffer from md5 a1778c... to 0858d4...; the superseded file is kept as required_960_extlen3_WRONG.bin.
  • tableT.json is a harness artifact, not the real S-box. It is _f0f17306(1), produced when an instrumentation stub replaced _aeb8ff4e with lambda: True. Every search was redone in an S-box- independent form (loop X over 0..255) as a result.
  • A reported 32-byte "hard-coded sentinel" in the validate routine was contamination, it was the value the instrumentation stub had itself fed in.
  • Two ctypes function pointers were misidentified; resolved by address against the live export tables: _10cb7a81 = kernel32!FlsGetValue, _6db9f204 = ntdll!RtlGetCurrentPeb.
  • FlsGetValue is declared restype=c_void_p, so a NULL slot yields None and the GUI aborts with "Something Wrong!", an anti-emulation gate, since under wine every FLS slot is NULL.
  • Before the stub was found, an enormous search space was ruled out against the corrected 960 bytes: every hashlib algorithm over ~25 encodings of t; HMAC and keyed blake2 with every embedded constant; AES-128/192/256 in ECB/CBC/CTR both directions; ChaCha20, Salsa20, RC4, TEA, XTEA; 16 bytes from MT19937, xorshift32/64/128, splitmix, PCG and four LCGs; the UPYX packer's own keystream in 18 variants; a full 2^32 seed sweep over 16 PRNG families; 3,930 enumerated "small program" transforms; and 294 H(char, index) combinations. Zero hits, which was the correct signal that the transform was held by a service, not computable offline.
  • Driving the real GUI: the button handler applies the Capslock flag to the button label, so with Capslock off the key labelled Q emits q. Feed the character, not the label.
