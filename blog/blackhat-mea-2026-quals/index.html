Before the writeups

How to read this.

Every section follows the same shape. What it was covers the surface the challenge exposed and what analysis showed. The bug is the precise root cause, not a hand-wave. Where it earns its place, the load-bearing code is quoted and the dead ends are named, because the dead ends are usually where the actual learning happened.

Fourteen of the fifteen yielded flags. Teto did not, and its section is here anyway: the reverse engineering finished, the primitives were validated in a byte-exact simulator, and the exploit design held up. It lost to an arithmetic budget, not to a misunderstanding. A writeup that only shows the wins is a sales deck, not a notebook.

Two of these, Qfact and Whisper, were solved fresh while writing this up, so those sections are first-hand rather than reconstructed from competition notes.

On the flags. Challenge instances are provisioned per run, so the flag values below are the ones our instances returned, not reusable answers. They sit behind a click because several of these challenges get recycled into training platforms, and a search engine result that spoils someone else's lab helps nobody.

The writeups.

Showing all 15 challenges

.01

Hokan

Prony / Ben-Or–Tiwari with a structured node set, then an LLL knapsack

Crypto 100 pts

What it was

Rebuild a secret 11-variable, degree-11 polynomial over an unknown 256-bit prime field from only 8 evaluations. Textbook Prony interpolation needs 10 for a 5-term polynomial, so the attack has to be near information-optimal.

The bug

The author assumed 8 evaluations sat safely under the interpolation threshold. They do not, provided you stop querying at random. If every query point is a scalar power-family of one weight vector, the integer left kernel of the evaluation matrix depends only on the multiset of exponent inner products: not on the coefficients, and not on p. That kernel is spanned by the locator polynomial's coefficients, so a correct guess at the node set yields a relation that is an exact integer multiple of p. The unknown modulus stops being the obstacle and becomes the thing you extract.

Flag

Captured BHFlagY{ea9380bc79fd02eefb1fbb538337a432}

Instances are provisioned per run, so this value is ours, not a reusable answer.

.02

Popcnt Oracle

RSA malleability plus popcount invariance under doubling, driven by beam search

Crypto 100 pts

What it was

The service is an unrestricted RSA decryption oracle that leaks exactly one bit of information: popcount(x^d mod n). Three doubling chains and roughly 2,051 queries each recovered all 2,048 bits of the secret in about 17 minutes.

The bug

Two flaws compose. First, sending x = c · k^e mod n makes the server compute k·m mod n, so the oracle answers for any attacker-chosen k. No padding check stops it. Second, popcount is not invariant under modular reduction, and the way it fails is informative: if 2y < n the value is a pure left shift and the popcount is identical, but if 2y ≥ n it wraps and the popcount usually changes. So a popcount change along a doubling chain proves a wrap, and for the chain seeded at m those wrap flags are literally the binary digits of m/n.

Flag

Captured BHFlagY{ecc3a2adc3ccb6a6120005fa8c5bfde3}

Instances are provisioned per run, so this value is ours, not a reusable answer.

.03

Reduce, Reuse, Recycle

GCM forbidden attack, UTF-8 length juggling, then a hex-alphabet collapse

Crypto 100 pts

What it was

AES-GCM key and nonce are reused on every encryption, while the plaintext contains the key's own hex. Half of each tag recovers the GHASH key H, multi-byte UTF-8 slides the key hex across block boundaries, and a quirk of the hex alphabet collapses a 248 ambiguity down to 216.

The bug

Nonce reuse in GCM destroys authentication: with H and E(J0) fixed, XORing two tags from equal-length messages cancels E(J0) and leaves a known polynomial in H over GF(2128). That is the classic forbidden attack. The subtler half is that same-length queries leak nothing about the key, because the key hex sits at a fixed offset and contributes identically to every GHASH, cancelling in every difference. Only a length change slides it across GHASH's 16-byte boundaries and turns it into new linear equations, and multi-byte UTF-8 is exactly the lever that changes length without changing the structure.

Captured BHFlagY{584bc40e6b665f84224a4f932eef4ebf}

.04

Qfact

Defender quarantine RC4 recovery, then ransomware key and IV, then AES-CBC decrypt

Forensics 100 pts

What it was

Windows Defender quarantined the ransomware, but the evidence set ships the quarantine store. Decrypt the store with the static MsMpEng RC4 key, read the AES key straight out of the dropper, rebuild the IV from host identifiers in the registry, and the victim's files come back.

The bug

Two decisions in the ransomware make full recovery possible. The AES key is a hard-coded literal in the dropper, obfuscated only by Chr() concatenation, and the dropper itself survives inside Defender's quarantine. The IV is derived from non-secret host identifiers, MD5(COMPUTERNAME + USERNAME), both recoverable from the registry hives in the same evidence set, with the computer name also printed in the ransom note. Defender's quarantine store is only obfuscated, not encrypted: every file is RC4 under a static, publicly documented 256-byte key compiled into MsMpEng.

Captured BHFlagY{d3f3nd3r_qu4r4nt1n3_r3c0v3ry_2026}

Instances are provisioned per run, so this value is ours, not a reusable answer.

.05

Whisper

Ollama prompt history, script recovered from Trash, blake2b-derived AES-zip password

Forensics 100 pts

What it was

An insider used a local LLM to build an exfiltration tool. The prompt log is an uncensored record of them designing it, passphrase included, and the script survives in the GNOME Trash along with the key derivation and the staging path.

The bug

This is not a software vulnerability, it is an artifact-retention failure, and the challenge is built on three of them. The local LLM keeps a plaintext prompt log at ~/.ollama/history that is never cleared, and the passphrase was typed straight into it alongside a step-by-step statement of intent. "Delete the script after successful execution" was implemented as a move to Trash, so cache_mgr.py is intact with its deletion timestamp. And the archive was staged in a cache directory that nothing ever cleaned up.

Flag

Captured BHFlagY{l0c4l_0ll4m4_llm_f4r3n51c5_2026}

Instances are provisioned per run, so this value is ours, not a reusable answer.

.06

baiby-pwn

Unbounded array write to GOT overwrite to FSOP leak to setcontext ROP

Pwn 100 pts

What it was

arr[i] = v with no bounds check, on a non-PIE Partial-RELRO binary, is an arbitrary aligned write across the whole writable page, GOT included. That turns into an FSOP libc leak on fd 2, then full register control via setcontext, then a raw syscall chain that reads a randomly-named flag file without ever calling execve.

The bug

case 1: arr[i] = v; performs a completely unchecked 8-byte store at 0x404080 + 8*i with attacker-controlled index and value. arr sits in .bss immediately above a writable GOT, so negative indices reach every PLT slot and every R_X86_64_COPY FILE* slot. The write looks weak on its own, since both operands are atol() of at most 7 characters, but the binary is non-PIE, so every code address and every writable-page address is representable inside that budget. That is enough to redirect any library call.

Captured BHFlagY{ac40504d9ee323d2995691bbe2825c43}

Instances are provisioned per run, so this value is ours, not a reusable answer.

.07

Teto

Full reverse engineering and validated primitives, blocked on the OR-write budget

Pwn 0 pts

What it was

The only challenge that did not fall. The reversing is complete, the exploitation primitives were validated in a byte-exact simulator, and the exploit design was sound. It died on an arithmetic budget, not on understanding.

The bug

Included here because the analysis finished even though the flag did not. The writeup documents the full reverse-engineering result, the verified primitives, the simulator-validated design, and the precise budget shortfall that blocked it. Several hours also went into a ret2dlresolve route that was clean on paper and never landed: setting the index through case 1 also performs an out-of-bounds store that faults, and the workaround conflicts with the GOT value the trigger itself requires.

Flag

Not captured. Analysis complete, exploit blocked on budget.

.08

Bug Where

io_uring double-free of an iovec to pipe_buffer UAF to kernel LPE

Pwn 100 pts

What it was

A real Linux 7.2.0-rc3 io_uring bug. Reclaim the freed chunk with a pipe_buffer[], issue a second bundled IORING_OP_SEND, and you write attacker-chosen pointers over pipe_buffer[0].ops, so close() calls into userland and commit_creds(prepare_kernel_cred(&init_task)) gives root.

The bug

io_ring_buffers_peek() calls kfree(arg->iovs) on the array it just filled instead of on the array it replaced. The fix in 7.2 final guards it with if (arg->iovs != org_iovs && (arg->mode & KBUF_MODE_FREE)) and frees org_iovs instead. The caller compounds it: io_send_select_buffer() hands the cached vec back in and only writes it back when the pointer actually changed, so a dangling iovec pointer stays parked in ctx->netmsg_cache.

Flag

Captured BHFlagY{16cb5f9913feed7e2b3f4883f774d103}

Instances are provisioned per run, so this value is ours, not a reusable answer.

.09

extended-license

eBPF-decrypted SIGTRAP shellcode, Feistel inversion, z3 username solve

Reversing 100 pts

What it was

A 34 MB stripped PIE hides its license check in 40 encrypted x86 shellcode chunks, decrypted inside the kernel by an embedded eBPF tracepoint program and dispatched through int3/SIGTRAP. The solve ends at a unique username, xorionxarcheryxseedx.

The bug

Three root causes chain together, and the first is the funniest: the bit-comparison oracle leaks the expected value in its own arguments. The final check compares the Feistel-transformed payload against a hard-coded 512-bit constant one bit at a time via syscall(0x1337, actual_bit, mode), reading the seccomp SECCOMP_RET_ERRNO return as the result. But the seccomp program has four parity arms selected by args[1], and the shellcode picks the arm according to the expected bit. The mode argument is the answer. Scraping 512 strace lines and reading args[1] off each one hands you the target directly.

Captured BHFlagY{BPF_c4n_b3_b4d_Bu7_I_d0n'7_Th1nK_7thIs_()ne_1s_B4D?_6b117fca1597}

Instances are provisioned per run, so this value is ours, not a reusable answer.

.10

free-agentic-tool

Go dropper to reflective PE stage 2 to deterministic X25519 key to pcap decryption

Reversing 100 pts

What it was

A "free" AI agent CLI, a session debug bundle, and a packet capture. The distributed binary is a dropper whose real payload is a reflectively-loaded second Go executable speaking gRPC to a C2, and that stage derives its X25519 private key instead of generating one, so the whole captured session decrypts from the pcap alone.

The bug

Two bugs, one hiding the other. The loader is disguised as archive/zip: the binary's zip package contains seven functions that do not exist in the Go standard library, all claiming to come from archive/zip/writer.go:666+, and together they form a reflective PE loader triggered by a planted sync.Once. The UI prints a fake HTTP 401 as cover. The second bug is the fatal one: stage two derives its X25519 private key as sha256(USERNAME + "_" + COMPUTERNAME), both of which the debug bundle hands you.

.11

upyx

UPX to PyInstaller to 100 marshal layers to a Cython RPC client to a VEH-packed C verifier

Reversing 100 pts

What it was

An 11.8 MB PE wrapped in UPX over PyInstaller over 100 nested marshal layers over a Cython GUI over a custom VEH packer. The final gate is a 960-byte keyed comparison that inverts cleanly, and the last hop hides in the UPX stub tail that upx -d throws away.

The bug

The hint is the key derivation, and it is sharper than it looks. check.pyd walks PEB to ProcessParameters to CommandLine, takes the characters after the last dot, keeps alphanumerics, lowercases, and FNV-1a hashes them with a non-standard basis of 0xB5F6F899 rather than 0x811C9DC5. So K = fnv1a("exe"). Rename the file and K changes and nothing validates, which is exactly what "don't rename this file" was telling you.

Flag

Solved on the day. Value not recorded in the report.

.12

Dead Drop

CSS-allowlist escape via </style>, then a CSS selector oracle against the bot

Web 100 pts

What it was

An anonymous dead-drop board validates a per-drop "envelope cipher" CSS field with a real CSS parser and a property allowlist, then echoes the accepted CSS verbatim into a <style> block. Under a JS-free CSP, a CSS selector oracle still drags the flag out one character at a time.

The bug

The validated CSS is reflected verbatim into <style>, and the validator has no notion of HTML context. The parser treats a CSS string literal as an opaque value, so anything inside quotes passes, including a{font-family:"</style><img>"}. During HTML parsing that inner </style> terminates the style element, because raw-text elements end at the first matching end tag and quotes mean nothing to the HTML tokenizer. From there, html:has(input[value^='...']) rules plus the same-origin pickup beacon turn the headless-Chrome courier into a character-by-character oracle.

Flag

Solved on the day. Value not recorded in the report.

.13

Lumen

Cross-parameter urldecode XSS plus max_input_vars CSP removal

Web 100 pts

What it was

A read-only document relay with a strict per-request nonce CSP on every page. Smuggle a < across a parameter boundary, then delete the CSP header entirely by making PHP emit a startup warning before the script runs.

The bug

Three distinct bugs, all required. clean() blocklists only the literal string %3c and then htmlspecialchars(), but index.php calls urldecode() on the concatenation after each half was sanitised separately. So %3e, %22, %27 and %26 are resurrected into real characters, and because dir and file are cleaned separately but concatenated before decoding, a dir ending in % joins with a file starting in 3c. Then sending more than 1,000 query parameters makes PHP print a max_input_vars warning at request startup, so the later header("Content-Security-Policy: ...") fails with "headers already sent" and the CSP simply never ships.

Flag

Captured BHFlagY{406d825cc9c3e881efbaa597ad7591c2}

Instances are provisioned per run, so this value is ours, not a reusable answer.

.14

DeckForge

file:// read, then an SOP-disabled cross-origin pivot to a privileged chromedriver

Web 100 pts

What it was

DeckForge turns attacker-supplied HTML into preview images. The renderer runs Chromium with --allow-file-access-from-files and --disable-web-security, which is an arbitrary local file read and a licence to drive a loopback chromedriver running as a different, more privileged user.

The bug

Three things compose. The attacker's HTML renders with --allow-file-access-from-files, giving an arbitrary local file read from a file:// origin. --disable-web-security removes the same-origin policy, so that page can issue arbitrary cross-origin requests to loopback and read the responses. And a second chromedriver listens on loopback as the runner user with --allowed-origins='*'. Its --allowed-ips=127.0.0.1 allowlist is worthless, because the attacker's code is already executing on 127.0.0.1.

Captured BHFlagY{9461dcd097931631fa22e5aed1f9e680}

.15

Huddle

SHA-256 length extension to owner, then ffmpeg dref arbitrary file read

Web 100 pts

What it was

A small team chat workspace. Length-extend the invite token to promote yourself to workspace owner, which unlocks the video thumbnailer, which shells out to ffmpeg with external data references enabled. Eight requests rebuild /flag.txt byte-exact.

The bug

The invite token is signed with a raw SHA-256 prefix MAC, sha256(SECRET ‖ "team=main&email=...&role=member"), not HMAC, so it is length-extendable. The parser makes it exploitable in exactly one direction: it is a hand-rolled split('&') where the last duplicate key wins, so appending &role=owner overrides the original role. Owner unlocks a thumbnailer that runs ffmpeg -enable_drefs 1 -use_absolute_path 1, and a hand-built MP4 carrying a Mac-alias external data reference plus a custom 256-entry pal8 colour table turns each thumbnail into one JPEG-lossless bit-plane of an arbitrary server file.

Flag

Captured BHFlagY{91c5fde3a1ef9948fac9a90a2a4545a3}

03

Afterwards

What the set rewarded.

Three of these were not really about the primitive at all. Hokan, Popcnt Oracle and Reduce, Reuse, Recycle each present a budget that looks one query, one bit or one block too small, and each one opens the moment you stop querying at random and start querying with structure. The lesson transfers directly to real work: an oracle that leaks one bit is still an oracle, and the interesting question is what you choose to ask it.

The web set punished trust in the wrong layer. Dead Drop validated CSS with a real CSS parser and still lost, because the parser has no idea it is writing into HTML. Lumen sanitised both halves of a path and then decoded the concatenation. DeckForge put an IP allowlist in front of a service the attacker was already executing inside. In all three the control was real and the boundary was imaginary.

Bug Where was the one that felt least like a puzzle. It is a genuine Linux 7.2.0-rc3 io_uring bug with a one-line fix in the final release, and the gap between frees the array it just filled and a root shell is a reminder of how little slack there is in kernel memory management.

And then Teto, which I still think was winnable. The analysis was right and the exploit design was validated in simulation. It ran out of write budget, which is a more annoying way to lose than being wrong.
