Before the writeups

How to read these.

Every writeup follows the same shape. Recon is what the challenge handed over and what analysis showed. The bug is the precise root cause, quoted from source where the source is the point. Exploitation is the chain that turns it into a flag, step by step, with the load-bearing code. Dead ends is where the hours actually went.

Fourteen of the fifteen yielded flags. Teto did not, and it is written up in the same detail anyway: the reverse engineering finished, the primitives were validated in a byte-exact simulator, and the exploit design held. It lost to an arithmetic budget, not to a misunderstanding. A writeup that only shows the wins is a sales deck, not a notebook.

On the flags

Challenge instances are provisioned per run, so the flag values are the ones our instances returned, not reusable answers. They sit behind a click because several of these get recycled into training platforms, and a search result that spoils someone else's lab helps nobody.

.01

Hokan↗

Prony / Ben-Or–Tiwari with a structured node set, then an LLL knapsack

Reconstruct a secret 11-variable degree-11 polynomial over an unknown 256-bit prime field from only 8 evaluations, two fewer than Prony interpolation nominally requires, by choosing query points whose structure makes the integer kernel depend only on the exponents.

.02

Popcnt Oracle↗

RSA malleability plus popcount invariance under doubling, driven by beam search

The service is an unrestricted RSA decryption oracle that leaks only popcount(x^d mod n); because 2y mod n is a pure left shift (identical popcount) exactly when 2y < n, a popcount change along a doubling chain proves a modular wrap, and for the chain seeded at m those wrap flags are literally the binary digits of m/n. Three chains (k = 1, 3, 5, 2051 queries each) driven through a beam search recovered all 2048 bits of the secret m in ~1020–1080 s, which was then submitted verbatim to get the flag.

.03

Reduce, Reuse, Recycle↗

GCM forbidden attack, UTF-8 length juggling, then a hex-alphabet collapse

AES-GCM key and nonce are reused on every encryption while the plaintext contains the key's own hex. Half of each tag recovers the GHASH key H; multi-byte UTF-8 characters slide the key hex across GHASH block boundaries; a hex-alphabet quirk collapses the residual 2^48 ambiguity to 2^16.

Qfact↗

Defender quarantine RC4 recovery, then ransomware key and IV, then AES-CBC decrypt

Windows Defender quarantined the ransomware but the evidence set ships the quarantine store. Decrypt the quarantine with the static MsMpEng RC4 key, read the AES key out of the dropper, rebuild the IV from host identifiers found in the registry, and decrypt the victim files.

.06

baiby-pwn↗

Unbounded array write to GOT overwrite to FSOP leak to setcontext ROP

arr[i] = v with no bounds check on a non-PIE Partial-RELRO binary is an arbitrary aligned write over the whole writable page, including the GOT. Repointing memset@got at main's third setbuf call site and setbuf@got at the read setup inside getval converts the "2" command into read(0, *0x404060, 0x40), a 64-byte arbitrary write, which forges an FSOP header in the real _IO_2_1_stderr_ to leak libc on fd 2, then points setbuf@got at setcontext with the slot aimed at a fake ucontext for full register control, and finally chains open/getdents64/read/write(2,…) to read the randomly-named flag file without ever calling execve (which Landlock restricts).

.07

Teto↗

Full reverse engineering and validated primitives, blocked on the OR-write budget

A Tetris implementation with an out-of-bounds cell write and a width field that can be corrupted into an arbitrary-length stack read. Both primitives were verified against the real binary and a working stack leak runs on the live target; the exploit stalls on an arithmetic budget, not on a missing idea.

.08

Bug Where↗

io_uring double-free of an iovec to pipe_buffer UAF to kernel LPE

Linux 7.2.0-rc3 ships an io_uring/kbuf.c bug where io_ring_buffers_peek() does kfree(arg->iovs) on the array it just filled instead of on the replaced array, while io_uring/net.c only refreshes kmsg->vec.iovec when a realloc actually happened, leaving a dangling iovec pointer parked in ctx->netmsg_cache. Reclaiming the freed chunk with a pipe_buffer[] and issuing a second bundled IORING_OP_SEND writes attacker-chosen (iov_base, iov_len) pairs directly over pipe_buffer[0].ops, so close() calls a userland pipe_buf_operations->release → commit_creds(prepare_kernel_cred(&init_task)) → root, then read the flag off /dev/sda.

.09

extended-license↗

eBPF-decrypted SIGTRAP shellcode, Feistel inversion, z3 username solve

A 34 MB stripped PIE hides its license check in 40 encrypted x86 shellcode chunks that are decrypted inside the kernel by an embedded eBPF tracepoint program (bpf_probe_write_user on syscalls:sys_enter_openat with dirfd 0x1337) and dispatched via int3/SIGTRAP. Dumping the chunks in a privileged container, reconstructing the 8×4-round Feistel/PRNG license transform, scraping the expected 512-bit target out of the seccomp ERRNO oracle's own argument stream, and z3- solving the 14 hidden username byte-checksums plus crc32(user)==0xbf2b0fa2 yields the unique username xorionxarcheryxseedx, whose derived 72-byte license.dat makes the untouched binary print the flag.

upyx↗

Dead Drop↗

CSS-allowlist escape via </style>, then a CSS selector oracle against the bot

The per-drop "envelope cipher" CSS field is validated by a real CSS parser with a property/ value allowlist, but the accepted CSS is echoed verbatim into a block, and a CSS string literal may contain , giving arbitrary HTML injection (including a second that never sees the validator). Under a JS-free CSP (default-src 'none'; style-src 'unsafe-inline'; img- src 'self'), the same-origin pickup beacon /px/:id logs the full request URL including query string into an owner-readable log, so html:has(input[value^='…']) #qN{background:url(/px/ COLLECTOR?p=N)} rules turn the headless-Chrome courier bot into a CSS-selector oracle that leaks the courier-only hidden one character at a time.

Lumen↗

Cross-parameter urldecode XSS plus max_input_vars CSP removal

A 1000 query parameters, which makes PHP print a max_input_vars request-startup warning before the script runs, so header("Content-Security-Policy: ...") fails with "headers already sent". The resulting unrestricted onerror handler reads the operator bot's localStorage.flag and posts it to the app's own ?p=trace note store, which the attacker reads back.

Huddle↗

SHA-256 length extension to owner, then ffmpeg dref arbitrary file read

Huddle signs invite tokens with sha256(secret ‖ "team=main&email=…&role=member") and parses them with a hand-rolled last-duplicate-key-wins splitter, so a SHA-256 length-extension appending &role=owner promotes any member to workspace owner. Owner unlocks the video- message thumbnailer, which shells out to ffmpeg -enable_drefs 1 -use_absolute_path 1; a hand- built MP4 with a Mac-alias (alis) external data reference plus a custom 256-entry pal8 colour table turns each thumbnail into one JPEG-lossless bit-plane of an arbitrary server file, and 8 requests reconstruct /flag.txt byte-exact.

Afterwards

What the set rewarded.

Three of these were not really about the primitive. Hokan, Popcnt Oracle and Reduce, Reuse, Recycle each present a budget that looks one query, one bit or one block too small, and each opens the moment you stop querying at random and start querying with structure. That transfers straight to real work: an oracle that leaks one bit is still an oracle, and the interesting question is what you choose to ask it.

The web set punished trust in the wrong layer. Dead Drop validated CSS with a real CSS parser and still lost, because the parser has no idea it is writing into HTML. Lumen sanitised both halves of a path and then decoded the concatenation. DeckForge put an IP allowlist in front of a service the attacker was already executing inside. In all three the control was real and the boundary was imaginary.

Bug Where felt least like a puzzle. It is a genuine Linux 7.2.0-rc3 io_uring bug with a one-line fix in the final release, and the distance between freeing the wrong array and a root shell is a reminder of how little slack there is in kernel memory management.

And then Teto, which I still think was winnable.
